亲手复验 · 六个步骤

REPRODUCE

在 Mac 终端执行。先进入项目目录；第 4 步定义的 k 函数供第 5 步使用，请在同一终端依次操作。

cd /path/to/mac-k8s-spark

如果在另一台电脑或解压后的目录中验证，将上面的路径替换为实际项目路径。首次运行需要联网下载组件与镜像。

01

启动 Kubernetes

./01-start-k8s.sh
echo "退出码=$?"

预期 K8S_READY instance=spark-k3s；退出码 0。

02

部署 Spark

./02-start-spark.sh
echo "退出码=$?"

预期 SPARK_READY 与 Pi 计算结果；退出码 0。

03

独立检测就绪

./03-check-spark.sh
echo "退出码=$?"

预期 Master ALIVE、Worker 已注册，实际完成 SparkPi；退出码 0。

04

直接检查集群

export LIMA_HOME="$HOME/.lima-mac-spark"
k() { ./.tools/bin/limactl shell spark-k3s sudo k3s kubectl "$@"; }
k get nodes
k -n spark-demo get pods
k -n spark-demo logs deployment/spark --tail=100

预期 节点 Ready；Spark Pod 为 1/1 Running；日志可见作业活动。

05

故障注入：停止 Spark

k -n spark-demo scale deployment/spark --replicas=0
k -n spark-demo wait --for=delete pod -l app=spark --timeout=60s
./03-check-spark.sh
echo "退出码=$?"

预期 此步骤会暂时停止演示 Spark。检测应退出 1，且没有 SPARK_READY 成功标志。

06

恢复与重复执行

./02-start-spark.sh
echo "退出码=$?"
./01-start-k8s.sh && ./02-start-spark.sh && ./03-check-spark.sh

预期 恢复后再次得到 Pi 结果；重复执行成功，复用同一 VM 和部署资源。

交付边界与修复记录

NOTES & SCOPE

实测发现并修复

  • CoreDNS 创建时序：先等待资源创建，再等待部署就绪。
  • 代理影响内部通信：为节点、Pod、Service 网段及集群域名设置 NO_PROXY。
  • Spark 监听地址：使用 Pod IP 通信，UI 使用默认全接口监听，探针与端口转发均可访问。
  • 失败处理：继承 ERR trap，限制无 Pod 时的等待，输出诊断并返回非零退出码。

已验证范围，不夸大承诺

  • 已在本机 Apple Silicon Mac 实测；Intel Mac 尚未验证。
  • 适用于最小化面试演示，不具备生产高可用保障。
  • 生产负载、长期稳定性、完整 Mac 重启后的恢复未验证。
  • 需要可用的虚拟化能力及外部镜像下载网络。此前沙箱阻塞已通过调整执行权限解决。
  • 18 项模拟检查是补充证据，不能替代真实运行。
